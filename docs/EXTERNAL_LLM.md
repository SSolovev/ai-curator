# Внешняя LLM и локальное обезличивание

Режим `external` предназначен для OpenAI Chat Completions API и совместимых с ним HTTPS-сервисов. Он выключен по умолчанию и требует отдельного разрешения вашей организации на передачу обезличенных рабочих данных внешнему поставщику. Описанный ниже privacy-конвейер является общим и обязательным также для `llama_cpp` и локальной основной модели Ollama.

Приложению нужен API-ключ выбранного поставщика. Ключ читается из файла секрета. Для OpenAI-совместимых сервисов используется заголовок `Bearer`, для Yandex AI Studio — `Api-Key` и идентификатор каталога. Схема ответа передаётся через `response_format`. [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat) · [Аутентификация Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication)

## Что происходит с данными

До первого сетевого запроса во внешний API backend выполняет локальный конвейер:

1. Реальные `source_ref` заменяются временными `SRC-0001`, `SRC-0002` и так далее. `employee_ref`, Jira key и отображаемое имя заменяются служебными маркерами.
2. Локальная модель Ollama, выбранная через `CURATOR_PII_FILTER_MODEL`, ищет персональные данные и названия организаций, включая бренды, сокращения и домены. Тег в примере конфигурации — `ai-curator-pii-gemma3-4b`.
3. Сервер находит в исходном тексте совпадения по обязательному словарю и шаблонам почты, телефона, логина и российских юрлиц с названиями в кавычках. Затем объединяет их с находками модели и заменяет пересекающиеся фрагменты целиком.
4. Во внешнюю модель поступает обезличенный контекст. Если запрос превышает порог и содержит комментарии, модель сначала извлекает из них события, затем формирует итоговый сценарий.
5. Схема запроса содержит допустимые обезличенные ссылки. После генерации сервер восстанавливает ссылки и даты, затем проверяет, что у фактов указаны источники и все ссылки есть в выбранном контексте.

Это fail-closed контур: если PII-модель недоступна, вернула некорректный результат, словарь отсутствует или пуст, внешний запрос не выполняется. При этом автоматическое обезличивание всё равно не даёт математической гарантии удаления любых чувствительных сведений. Используйте режим только после организационной и юридической проверки поставщика, условий хранения данных и состава контекста.

Код внешнего контура изолирован:

- `src/ai_curator/external_llm.py` — внешний OpenAI-compatible клиент и сборка runtime;
- `src/ai_curator/privacy_filter.py` — локальная PII-модель, словарь, regex и псевдонимы источников;
- `prompts/pii_filter.system.txt` — отдельная инструкция PII-модели.

## Однократная подготовка

Подготовьте `.env` и HMAC-ключ по [инструкции запуска](INSTALL_MANAGER.md). Установите и запустите native Ollama. Следующая команда скачивает Gemma 3 4B и создаёт локальный тег фильтра.

```bash
./scripts/prepare-ollama.sh pii-filter
ollama show ai-curator-pii-gemma3-4b
```

На PowerShell:

```powershell
PowerShell -ExecutionPolicy Bypass -File scripts/prepare-ollama.ps1 pii-filter
ollama show ai-curator-pii-gemma3-4b
```

Обычный `start` модель не скачивает.

## Секрет и словарь

Создайте `secrets/external_llm_api_key`, вставьте туда только API-ключ и ограничьте права файла. Не помещайте ключ в `.env`, исходный код, URL или команды shell.

```bash
chmod 600 secrets/external_llm_api_key
```

Создайте непустой `secrets/pii_dictionary.txt`: одна строка — один фрагмент для регистронезависимой замены. Пустые строки и строки, начинающиеся с `#`, игнорируются. Можно начать с безопасного шаблона:

```bash
test -f secrets/pii_dictionary.txt || cp docs/pii_dictionary.example.txt secrets/pii_dictionary.txt
chmod 600 secrets/pii_dictionary.txt
```

```text
# ФИО, варианты написания, логины и внутренние идентификаторы
Иван Иванов
ivan.ivanov
Команда Секретного Проекта
```

Для каждой организации добавляйте отдельными строками юридическое название, разговорные сокращения, домены, варианты на латинице, формы с пробелом, дефисом и подчёркиванием. Совпадение ищется без учёта регистра по буквальной подстроке. Для неоднозначных коротких сокращений проверьте на демо, какие ещё слова они маскируют. Перезапустите приложение после изменения словаря. Имя и Jira key выбранного сотрудника также автоматически добавляются во временный словарь текущего запроса.

## Включение

Получите у поставщика базовый HTTPS-адрес API, точный ID модели и API-ключ. Клиент проверяет доступность через `GET /models`, генерирует через `POST /chat/completions` и передаёт формат ответа `response_format.type=json_schema`. Проверьте поддержку схемы, сформировав сценарий на демо Jira.

Укажите в `.env` значения своего поставщика. Ниже приведён пример для OpenAI.

```dotenv
CURATOR_LLM_RUNTIME=external
CURATOR_EXTERNAL_LLM_ENABLED=true
CURATOR_EXTERNAL_LLM_BASE_URL=https://api.openai.com/v1
CURATOR_EXTERNAL_LLM_MODEL=gpt-4.1-mini
CURATOR_EXTERNAL_LLM_API_KEY_FILE=/secrets/external_llm_api_key

CURATOR_PII_FILTER_BASE_URL=http://host.docker.internal:11434
CURATOR_PII_FILTER_MODEL=ai-curator-pii-gemma3-4b
CURATOR_PII_FILTER_DICTIONARY_FILE=/secrets/pii_dictionary.txt
```

Запустите:

```bash
./scripts/start.sh
docker compose logs app --tail 100
```

В «Модель и защита данных» должны одновременно быть доступны внешняя модель и `privacy_filter`. Если локальный фильтр unhealthy, генерация заблокирована до исправления.

Порог прямого запроса к внешней модели задаёт `CURATOR_EXTERNAL_LLM_DIRECT_PROMPT_CHARS`. По умолчанию запрос с обезличенными комментариями отправляется напрямую при суммарной длине сообщений и схемы до 36 000 символов. Для более длинных запросов модель сначала извлекает события из комментариев.

### Qwen3.6 35B через Yandex AI Studio

Скопируйте идентификатор каталога и создайте API-ключ в этом же каталоге. Сохраните секретную часть ключа в `secrets/external_llm_api_key`. Для генерации нужна область действия `yc.ai.foundationModels.execute`, а для проверки через список моделей — `yc.ai.models.viewer`. [Быстрый старт AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/quickstart/) · [Получение списка моделей](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/models/get)

В `.env` замените значения ниже и подставьте свой идентификатор каталога вместо `FOLDER_ID`.

```dotenv
CURATOR_LLM_RUNTIME=external
CURATOR_EXTERNAL_LLM_ENABLED=true
CURATOR_EXTERNAL_LLM_BASE_URL=https://ai.api.cloud.yandex.net/v1
CURATOR_EXTERNAL_LLM_MODEL=gpt://FOLDER_ID/qwen3.6-35b-a3b
CURATOR_LLM_REASONING_EFFORT=none
CURATOR_LLM_MAX_TOKENS=6000
CURATOR_EXTERNAL_LLM_DIRECT_PROMPT_CHARS=36000
```

Клиент определяет каталог по URI модели, передаёт его в заголовках Яндекса и отключает логирование содержимого запроса через `x-data-logging-enabled: false`. Запустите `./scripts/start.sh`, проверьте основную модель и локальный фильтр в блоке «Модель и защита данных». Затем сформируйте сценарий на демо Jira, чтобы проверить совместимость структурированного ответа. [Каталог моделей](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models) · [Логирование запросов](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging)

Базовый адрес API заканчивается на `/v1`. Два рабочих пути клиент добавляет сам. Если проверка списка моделей проходит, а демо-генерация завершается ошибкой, смотрите логи приложения и код ответа провайдера. [Как смотреть логи](TROUBLESHOOTING.md#где-смотреть-логи)

### Проверка обезличивания в демо Jira

1. Выберите «Демо Jira» и откройте Марию Сергеевну Тестову (`DEMO-667`). В исходном предпросмотре будут видны вымышленные имена, адрес, телефон, почта, логин и табельный номер.
2. Для теста словарной замены добавьте строки `ООО «Демо-Контур 667»`, `Демо-Контур 667` и `DEMO-HR-00667` из примера в действующий локальный словарь. Название компании скрывается словарём. Перезапустите сервис, чтобы перечитать словарь.
3. На время проверки включите `CURATOR_LLM_LOG_REQUEST_RESPONSE=true`, выполните генерацию на демо и локально проверьте тело запроса в событии `external_llm_request_payload` или `llm_request_payload`. В нём должны быть маркеры замены и ссылки `SRC-…`. Проверьте, что исходных тестовых значений в теле запроса нет.
4. После проверки верните `CURATOR_LLM_LOG_REQUEST_RESPONSE=false` и перезапустите сервис. Точная проверка одной подборки примеров характеризует только эту подборку и выбранную конфигурацию фильтра.

## Возврат к локальной модели

Например, для Qwen 8B:

```dotenv
CURATOR_LLM_RUNTIME=ollama
CURATOR_OLLAMA_MODEL=ai-curator-qwen3-8b
CURATOR_EXTERNAL_LLM_ENABLED=false
```

После изменения повторите `./scripts/start.sh`. Для Docker `llama.cpp` установите `CURATOR_LLM_RUNTIME=llama_cpp` и также верните opt-in в `false`.

## Логи

При `CURATOR_LLM_LOG_REQUEST_RESPONSE=true` внешний клиент логирует только уже обезличенный запрос и ответ событиями `external_llm_request_payload` и `external_llm_response_payload`. Сырой запрос локальной PII-модели намеренно не логируется даже при этом флаге. Итог `pii_filter_completed` содержит только время, число проверенных текстов и число замен.

После диагностики верните флаг в `false`: обезличенный контекст и ответ всё равно могут содержать внутреннюю рабочую информацию.
