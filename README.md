# ИИ-Куратор

Privacy-first приложение для подготовки бережной встречи 1:1. Оно читает доступные куратору данные Jira, даёт проверить контекст, запускает выбранный runtime и проверяет, что фактические выводы ссылаются только на источники из переданного контекста.

Перед любой основной моделью — `llama.cpp`, native Ollama или `external` — контекст обязательно проходит отдельную локальную PII-модель, словарный фильтр, regex и замену идентификаторов источников. Контур fail-closed: без исправного фильтра основная модель не вызывается. В локальных runtime данные не уходят во внешние AI API; `external` включается только явно. Jira используется только на чтение. Приложение не предназначено для диагностики или автоматических кадровых решений.

## Быстрый старт

Нужны Docker с Compose, запущенная Ollama на компьютере, 32 ГБ оперативной памяти и минимум 16 ГБ свободного места. Docker запускает приложение и основную модель по умолчанию. Ollama запускает обязательную модель обезличивания.

```bash
test -f .env || cp .env.example .env
./scripts/prepare-model.sh
./scripts/prepare-ollama.sh pii-filter
test -f secrets/pii_dictionary.txt || cp docs/pii_dictionary.example.txt secrets/pii_dictionary.txt
# заполните словарь организационными именами, логинами и идентификаторами
CURATOR_LLM_RUNTIME=llama_cpp ./scripts/start.sh
```

Откройте <http://127.0.0.1:8080>. Jira PAT введите в форме: по умолчанию он останется только в памяти сессии. Для Docker secret создайте `secrets/jira_token` с правами только владельца; этот путь исключён из Git.

Для native Ollama с основной Gemma 4 12B или более лёгкой Qwen3 8B используйте пошаговую инструкцию [«Запуск AI Curator с Native Ollama»](docs/OLLAMA_MODELS_QUICKSTART.md). Для возврата к Docker установите в `.env` `CURATOR_LLM_RUNTIME=llama_cpp`. Скрипт запуска освобождает ресурсы невыбранного runtime; технические параметры описаны в [docs/CONFIGURATION.md](docs/CONFIGURATION.md).

Для разрешённого вашей организацией внешнего OpenAI-compatible API используйте отдельную инструкцию [«Внешняя LLM и локальное обезличивание»](docs/EXTERNAL_LLM.md). Этот режим не включается автоматически.

Полная простая инструкция: [docs/INSTALL_MANAGER.md](docs/INSTALL_MANAGER.md). Архитектура и границы: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Проверка без реальной Jira

Mock Jira запускается вместе с приложением. На первом экране выберите «Демо Jira — вымышленные данные» и нажмите «Проверить подключение»: адрес и демо-токен подставятся автоматически. Демо повторяет используемые типы полей рабочей Jira и возвращает 50 синтетических комментариев, но не содержит сведений реальных сотрудников.

## Разработка и тесты

Команды выполняются из корня проекта. Для тестов достаточно Python 3.12. Тесты используют вымышленные данные и подменяют запросы к моделям.

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
./scripts/test.sh
```

Команда `./scripts/smoke-container.sh` собирает Docker-образ и проверяет запуск и ответ `/healthz`. После подготовки весов `./scripts/benchmark-model.sh` проверяет основную модель отдельно.

## Важные каталоги

- `src/ai_curator/main.py` содержит маршруты FastAPI, а `service.py` связывает Jira, обработку контекста и модели.
- `src/ai_curator/static/` содержит HTML, корпоративную палитру и JavaScript интерфейса.
- `prompts/` и `schemas/` содержат инструкции моделям и формат ответа.
- `mock_jira/` и `tests/fixtures/` содержат демо Jira и вымышленные данные для проверок.
- `models/` содержит инструкции Ollama и контрольную сумму Docker-модели. Веса моделей загружаются отдельно.
